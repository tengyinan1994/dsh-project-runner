# dsh-project-runner（项目运行器）

**中文** | [English](README.md)


在 DeepSeek Harness 里做一个「一键起项目」的启动器：**分组 + 启动项**，每条启动项就是
「一条命令行 + 一个工作目录」，点一下用**真 PTY 开一个 zsh** 在对应目录执行它，输出实时
回到右边的日志面板。

**它不解析 `.vscode/launch.json`。** 这是刻意的：launch.json 是 DAP 调试配置格式，
`type` / `request` / `classPaths` / `program` 都是给调试器看的——java 的 `$Auto`、go 的
`dlv`、`pwa-chrome` 的 `url` 全部要扩展介入才有意义。run-only 翻译在 java / go / 浏览器
三类上注定别扭（本项目第一版就是这么做的，结果是某个 Java 项目那 9 条配置全灰）。
所以真源改成插件自己管的清单：**你写什么命令，就跑什么命令**。

```
 左侧栏「启动器」 ──▶ 主面板
┌───────────────────────────────┬────────────────────────────────────────────┐
│ ▾ demo-api   3 items          │ Admin Service            ● 运行中   [停止] │
│   ~/work/demo-api             │ mvn -pl :admin-service spring-boot:run     │
│   ● Admin Service   运行 ⋯    │ dir ~/work/demo-api/backend                │
│   ● HTTP collector  运行 ⋯    │ ────────────────────────────────────────── │
│   ○ build all   任务   运行 ⋯ │ 12:01:03 INFO  Started AdminApplication    │
│ ▾ demo-web   2 items          │ 12:01:04 INFO  Tomcat started on :8080     │
│   ~/work/demo-web             │ ...                                        │
│   ○ Vite dev        运行 ⋯    │                                            │
└───────────────────────────────┴────────────────────────────────────────────┘
```

界面按「**大纲树 + 详情头**」组织，层级不靠字号、靠形态：

- **分组 = 章节头**：顶格、粘顶、带一条**项目色条**（同一个分组永远同一个颜色）、
  上下有分隔线，右侧是「＋ 条目 / ⋯」。整块标题区（含目录那一行）都是折叠热区。
- **条目 = 缩进行**：无边框，靠**斑马纹 + 发丝分隔线**一条条隔开；行内只留
  「状态点 + 名称 + 状态胶囊 + 命令（附相对目录）」，操作只留「运行/停止」和「⋯」。
- **右栏 = 选中条目的详情头 + 实时日志**：命令、目录、环境变量、运行事实（pid /
  首字节 / 起止时间）都在这里，点左边任意一条即切换。
- **⋯ 菜单**：编辑 / 复制命令 / 上移 / 下移 / 改成另一种性质 / 删除。删除会二次确认。
  菜单用 `position: fixed` 并按触发按钮的矩形算坐标（右边缘对齐 + 视口夹取 + 下方放不下就往上翻）——
  左栏是 `overflow: auto` 的滚动容器，`absolute` 定位会被它**裁掉**（"删除分组"右边缺一截就是这么来的）；
  分组菜单与条目菜单各自独立标记，同一时刻只会有一个。
- **颜色只表达状态**：运行中绿、退出/停止中琥珀、失败红、未跑灰；其余保持中性，
  这样「有颜色」就等于「有信息」。

## 为什么放在全局面板区、并且是多分组

`sidebar.panellist` 在 DSH 里的定义是「Global panels（全局面板）」，跟「插件」「自动化
任务」同座——这一座天然是**跨会话、跨项目**的东西。启动器回答的问题是「我现在挂着哪些
服务、别把哪个忘了」，而你手里几个项目的服务同时在跑是常态；塞进
某个会话（右侧栏、对话内）反而要求你「先找对那个会话才能停掉一个服务」。所以它留在
全局区，并因此支持**多个分组并列**。

## 数据存在哪

`$DSH_HOME/launcher/items.json`（本机 `~/.dsh/launcher/items.json`）。**不往你的项目里
写任何文件**：项目里的 `.vscode/` 属于项目，本机的启动习惯属于你。

```json
{
  "schemaVersion": 1,
  "groups": [
    {
      "id": "g-…", "name": "demo-api", "dir": "~/work/demo-api",
      "items": [
        {
          "id": "i-…", "name": "MQTT采集", "kind": "service",
          "command": "mvn -pl :http-collector spring-boot:run",
          "cwd": "backend", "env": {}
        },
        { "id": "i-…", "name": "构建全部", "kind": "task", "command": "mvn -Pdev install -DskipTests", "cwd": "", "env": {} }
      ]
    }
  ]
}
```

`kind` 只有两个值：`service`（常驻服务，默认）与 `task`（一次性任务）；旧清单没有这个
字段，读回时按 `service` 处理。面板里改、或直接手改这个文件都行——打开面板时会重读。上一版的
`~/.dsh/launcher-projects.json`（项目列表）会在首次启动时**一次性迁移成分组**
（目录已填好，条目自己加），旧文件保留不动。

## 用法

1. 点左侧栏「启动器」→「＋ 新建分组」：填分组名（例如项目名）+ 默认工作目录。
2. 组里点「＋ 条目」：填名称、**性质**、命令行、工作目录（留空就用分组目录）、
   环境变量（每行 `KEY=VALUE`）。名称留空就用命令行首行。
3. **列表里的条目行只有名称**（命令、目录、环境变量、性质都在**右栏详情**里，选中即见）——
   行尾一个 ▶ 图标即运行，在跑时变成 ■ 图标即停止。列表是"选哪个"的界面，
   详情是"它到底是什么"的界面，不重复。
4. 点条目行 → 右栏显示它的命令/目录/环境变量；点 ▶ 就跑起来，输出实时进日志区。
   停止是 SIGINT（等于 Ctrl+C），强制结束才整棵进程树 terminate。
5. 编辑 / 复制 / 调序 / 改性质 / 删除都在行尾的「⋯」里；顶部有筛选框。

### 宿主版本协商（能力清单）

`/state` 带一个 `capabilities` 列表，客户端据此判断宿主半侧是不是旧版：

| 能力 | 缺少时的表现 |
|---|---|
| `item-kind` | 条目的「性质」保存不上 |
| `group-color` | 分组颜色保存不上（**旧宿主会静默忽略 color 字段**，点色块看起来"没反应"） |

缺能力时面板顶部会直接写出「宿主半侧是旧版：…要重启 DSH 之后才会保存」，色块也会**禁用并说明原因**——
而不是让你点了以为坏了。这是踩过两次的坑（`item-kind` 一次、`group-color` 一次），所以固化成机制。

### 主题（浅色 / 深色）

**只用 DSH 真正提供的 14 个颜色 token**，而且**不写硬编码兜底**——这两条都有测试盯着
（`client.test.mjs` 里那条会扫描 `client.js` 的 `var(--dsw-*)` 用法）：

- 用错 token 名 → 浏览器回落到兜底色 → **深色主题下必然错**（这是真踩过的坑：
  `fill-l1/l2`、`label-tertiary`、`bg-elevated`、`state-warning-primary`、
  `state-business-primary` 这些名字 DSH 都没有）。
- 兜底色本身就是"另一种主题的颜色"，所以颜色 token 一律不带兜底。

日志的 **ANSI 调色板分浅色/深色两套**，并按 `theme/change` 事件实时切换：

- 一套色不可能同时活在白底和深底上——ANSI 的「黑」(30) 在深色主题里看不见，
  「白」(37/97) 在白底上同样看不见（真实终端也这么处理）；
- 每一色对所在底色都保证 **对比度 ≥ 2.5:1**，由测试逐色断言；
- 浅色主题里「白」映射成深灰：这是日志查看器不是仿真终端，**可读性优先**。

语义色胶囊（运行中/异常/失败）用**实心语义色 + 底色文字**：语义色在深色主题里偏亮、
浅色主题里偏深，而底色与之天然相反，所以这组配色两种主题都成立。

### 行首那个圆点表示状态

**没在跑就不画点**，只有两种情况有点：

| 点 | 含义 |
|---|---|
| **绿点** | 正在运行（含启动中/停止中） |
| **红点** | 异常退出 / 启动失败 |
| 不显示 | 没跑过 / 已停止 / 已完成 / 服务正常退出 |

不显示时留一个等宽占位（`visibility: hidden`），否则名称会随状态左右跳动。
状态文字（含退出码）挂在圆点的 tooltip 上；**没有点的时候挂在名称的 tooltip 上**，
所以"它上次跑成什么样"随时查得到。运行/停止图标也带 `aria-label` 与 tooltip。

> 注意：按这个规则，`已退出（本该常驻）`（常驻服务退出码 0，琥珀色）现在**不显示点**——
> 它是个 settled 状态。如果想让这种"本该一直跑着却退了"的情况也留个琥珀点，说一声。

### 分组颜色

分组名左边是一个**圆角色块**，点它就能改色（一排预设色 + 「自动」）：

- 调色板是**马卡龙色系**（8 色：雾蓝 / 薄荷绿 / 蜜桃橙 / 薰衣草 / 樱花粉 / 湖青 / 奶油黄 / 抹茶绿）。
  选色有三条硬约束，**都有测试盯着**，免得以后手滑塞进一个深色：
  亮度 L ≥ 0.72（柔和不刺眼）、彩度跨度 30–110（太低发灰、太高就不叫马卡龙）、
  两两 RGB 距离 ≥ 30（色块只有 10px，糊成一片就失去"一眼区分分组"的意义）。
  色块带 1px 半透明描边——浅色在小尺寸下必须有边界，否则会糊进背景。
- 不指定颜色时按分组 id **派生**一个稳定颜色（老行为，新建分组照样有色）；
- 指定后写进清单文件（`color: "#rrggbb"`），**跨重启保留**；
- 宿主只接受 6 位十六进制，非法值当"自动"——不让任意字符串进到 style 里。


### 两种性质：常驻服务 vs 一次性任务

| 性质 | 跑完/退出时面板怎么说 |
|---|---|
| **常驻服务**（默认） | `已退出（本该常驻）` 琥珀色 —— 采集器悄悄退了是事故，要看得见 |
| **一次性任务** | 退出码 0 → `已完成` 绿色；非 0 → `失败（退出码 N）` 红色 |

所以「构建全部」这类命令建议设成**一次性任务**，采集器/后端保持**常驻服务**。
条目行尾的「⋯」菜单里可以一键切换。

**删除只删定义。** 移除分组、条目或运行实例都不会顺手杀掉正在跑的进程——整理面板不该
把你的服务弄停，要停就点「停止」。

## 安装

包自带 `dsh.bundle.patch`，装完即可用，**不需要手改 profile 的 `cordis.patch.yml`**：

```sh
# 从 npm
dsh plugin --profile desktop add dsh-project-runner

# 从 GitHub（纯 JS、无构建步骤）
dsh plugin --profile desktop add github:tengyinan1994/dsh-project-runner

# 本地目录（开发时用）
dsh plugin --profile desktop add link:/path/to/dsh-project-runner
```

装完**重启 DSH**（宿主半侧要起路由与 PTY 监督器）。

> **改过 `index.js` / `lib/*.js` 之后必须重启 DSH。** Node 的 ESM 缓存是进程级的，
> 停用再启用 bundle 不会重新 import——这一点已实测：禁用/启用后路由仍在，但跑的是旧模块。
> `client.js` 的改动不用重启（客户端 bundle 按 mtime 派生 revision，页面会自己拉新的），
> 不过客户端依赖宿主接口时，两边要一起生效；面板检测到宿主是旧版时会直接提示「重启 DSH」。

### 它碰你机器的哪些地方

公开插件应当把这件事写清楚，所以逐条列出来：

| 行为 | 说明 |
|---|---|
| 起进程 | 用 `ctx.subprocess.spawnTerminal` 开**真 PTY**，以**你自己的用户权限**执行你写的命令行；命令来源只有你自己的清单，插件不会拼命令 |
| 环境变量 | 默认 `inheritEnv: full`：像真终端一样继承你当前 shell 的全部环境变量——**包括** `*_KEY` / `*_TOKEN` / `*_SECRET` 这类（否则前端拿不到 `VITE_*_KEY`）。不想这样就设 `inheritEnv: scrubbed` |
| 写文件 | 只写 `$DSH_HOME/launcher/`：`items.json`（清单）与 `logs/`（运行日志）。不碰你的项目目录 |
| 网络 | **不联网**。没有遥测、没有外部请求；HTTP 面只注册在 DSH 自己的 webServer 上（同源、仅回环，非回环来源直接 403） |
| 依赖 | 零运行时依赖，不加载任何第三方包 |
| 删东西 | 删除分组/条目/运行记录都**不会**杀正在跑的进程；日志按天数 + 总量两道闸自动清理（默认 7 天 / 512MB） |

> 数据目录是 `$DSH_HOME/launcher/`（沿用旧名，与包名解耦）——升级或改名都不会丢已有清单。

## 配置

在 profile 的 `cordis.patch.yml` 里按 `launcher` 行 id 覆盖（字段注释见包的
`cordis.patch.yml`）：

| 字段 | 默认 | 说明 |
|---|---|---|
| `shellPath` | 本机 zsh | 空则按 `$SHELL → /bin/zsh → /bin/bash → /bin/sh` 回退 |
| `shellArgs` | `[-lic]` | 登录+交互+执行命令。**改 `-lc` 会快 ~13 倍，但丢 `.zshrc` 里的 PATH** |
| `maxRuns` | `12` | 同时保留的运行实例上限（所有分组共享） |
| `logMaxChars` | `400000` | 单实例日志上限，超出从**头部**丢弃（尾部永远保留） |
| `stopGraceMs` | `3000` | 停止时先 SIGINT，超时后整棵进程树 terminate |
| `inheritEnv` | `full` | `full` = 像真终端一样继承你当前全部环境变量（含 `*_KEY`）；`scrubbed` = 跟内置终端一样剔除敏感变量 |
| `cols` / `rows` | `160` / `40` | PTY 尺寸，影响按宽度换行的输出 |
| `storeFile` | 空 | 清单文件；空 = `$DSH_HOME/launcher/items.json` |
| `logDir` | 空 | 日志落盘目录；空 = `$DSH_HOME/launcher/logs` |
| `logRetentionDays` | `7` | 日志保留天数（按日期目录整目录清理） |
| `logFileMaxBytes` | `20971520` | 单文件上限，超过后只停止落盘（面板仍可看环形缓冲） |
| `logMaxTotalBytes` | `536870912` | 日志总量上限（512MB），超过就删最旧的 |

### 关于首字节耗时

`shellArgs: [-lic]` 会加载 `.zprofile` + `.zshrc`，本机 `.zshrc` 较重（gitstatus / nvm /
pyenv 之类），实测首字节 **1.6–2.4s**；`-lc` 只要 **0.12s**，但跳过 `.zshrc`。面板状态栏
会显示每次运行的「首字节」耗时，觉得慢就把 `shellArgs` 换成 `-lc`。默认选 `-lic` 是因为
启动器最怕的是「我的命令找不到」，而不是慢两秒。

## 日志与「回到对话排查」

### 日志落盘

每个运行实例同时写一份普通文本：`$DSH_HOME/launcher/logs/<日期>/<分组>__<条目>__<runN>.log`。
- **跨 DSH 重启还在**（内存环形缓冲会随进程消失，文件不会）；
- 面板详情头里显示路径，可一键「复制路径」；
**自动清理有两道闸**（都不需要你手动管）：

| 闸 | 默认 | 行为 |
|---|---|---|
| 按天保留 | `logRetentionDays: 7` | 日期早于 7 天前的目录**整目录删** |
| 按总量 | `logMaxTotalBytes: 512MB` | 超过就把**最旧的日志文件逐个删到线下**，删空的日期目录顺手清掉 |

清理时机是**插件挂载时 + 每个实例启动时**（各进程一次）——挂载就清是为了不让清理依赖
「你恰好启动了某个实例」这件事。单文件还有 `logFileMaxBytes`（默认 20MB）：超过后只是
**停止落盘**（文件里留一行说明，面板仍能看内存环形缓冲），不会轮转文件。

删掉的只有日志文件本身：运行实例记录、清单（`items.json`）都不受清理影响。

### 右栏「运行日志」tab：和对话同屏 + 滑选引用

`main` 是 keyed 单槽，**启动器和对话都想占它，天生无法同屏**。所以日志视图放在
**右侧栏**：主面板中间是对话，右栏是「运行日志」，两者同屏。

- 右栏「＋」里选「运行日志」即可打开。类型清单里那个图标是插件自己画的（一页带折角的文本 +
  三行输出）——注册 tab 类型时不给 `icon` 的话，侧栏只能拿默认兜底（一个方盒，跟日志没关系）。
- 日志**带行号**，直接滑选，松开鼠标时**选区旁边就浮出「添加到对话」**（不做成页脚固定按钮：
  这东西是选区驱动的，出现在你刚选完的地方才顺手）。取消选择、按 Esc、滚动日志都会收起它。
- 点它 → 往**对话输入框**追加一句引用（`inputActions.setDraft`，这是 DSH
  唯一公开的输入框写入 API，只有右栏 tab body 这类插槽拿得到）：

  ```
  【启动器日志 run-4 · Admin Service 第 12~45 行】
  ```

  写进去的是**变量**而不是日志正文——既不把十万字符塞进对话，引用本身又自带定位信息。
  你接着写问题、发送，模型看到这个引用就会用 `launcher_log` 带 `range: "12~45"` 去取那几行。

  > 关于「给这段上色」：**做不到**，三条证据都在代码里——① `setDraft` 的实现是
  > `root.clear()` + 逐行 `$createTextNode`（纯文本节点，无格式）；② DSH 自己的引用 chip 靠
  > 私有区占位符（`U+E100–U+E11D`/`U+FFFC`）表示，而 `setDraft` 会 `replace` 掉它们
  > （注释写明是防止伪造 chip 位）；③ 用户消息在对话里的渲染走 `projectUserText`（纯文本 +
  > 引用标签），不走 markdown。所以标记的辨识度只能靠符号本身：现在用 **`【】`** 包起来，
  > 在全角标点里这是最强的「这是一段被引用的东西」边界。
  >
  > 真想要彩色 chip 的话，需要 DSH 暴露「插入引用」的输入框 API（`inputActions` 目前只有
  > `setDraft`/`setView`/`openView`），这是内核侧的事。
- **在右栏就能管服务**：标题行右侧按状态给动作——在跑时「停止」（SIGINT，等于 Ctrl+C）/
  「强制结束」（整棵进程树 terminate）；「清空日志」**任何时候都有**（"这屏太乱先清一下、
  服务继续跑"是常见需求）；已结束时多一个「移除」（只从列表拿掉记录，日志文件仍在磁盘上）。
  理由很直接：你往往正是**盯着一段卡住的输出**才发现要停它，这时跑回启动器面板找条目是反向操作。
- 「清空日志」清的是**面板里那份缓冲**（宿主环形缓冲 + 客户端本地副本各清一次），**磁盘上的
  日志文件不动**；清完会明确显示「面板里的日志已清空」并给出文件路径，而不是含糊地显示
  「等待输出…」——后者是之前一个真 bug 的表象：只清了宿主侧、本地那 10 万字符还攥在手里，
  界面看起来就是"点了没反应"，切走再回来又变成一片空白。
- 页脚只有一个**字号**调节（`A-` / `A+`，9–20px，和启动器面板的日志区共用一份记忆，跨刷新保留）。
  日志文件路径在标题栏，点一下即复制。
- 顶部的**运行实例切换器是分段控件**：一条轨道 + 当前项浮起（白底 + 轻阴影 + 加粗），
  每一段前面带状态点（运行中绿 / 已停止灰 / 失败红），横向滚动而不是换行堆两排；
  同名实例只在**非当前项**上补 `· run-N` 后缀，当前项右侧单独挂 id，不重复。
- **切换器与「跟随最新」只在有两个以上实例时出现**：一个实例都没有（或只有一个）时，
  它们既没作用也让人费解——零实例时头部只留标题与一句空态。
- 「跟随最新」是个小胶囊开关（不用浏览器原生 checkbox）：默认打开——面板永远看着最近一次
  **失败**的运行；关掉就钉在你看的那条上（文案变「已钉住」）。

### 拖拽排序 / 拖拽换组

- **分组**：整块标题是拖拽把手——拖动排序，落点画一条插入线。
- **条目**：整行是拖拽把手——同组内拖动排序；**拖到别的分组里即换组**（拖到分组标题上 = 放进该组）。
- 被拖的行/分组会变淡；落点画一条 **3px 的插入线**（左端有小方块当箭头，压在行缝上）：
  上半区插在目标之前、下半区插在之后。**「放到末尾」也有线**——分组线画在最后一个分组的下沿。
- 落点是**逐层精确判定、绝不互相覆盖**：行的处理函数接受这次落下才 `preventDefault`，
  并**阻止冒泡**（不阻止的话事件会冒到分组区域、把"插在这一行之前"改写成"追加到末尾"，
  结果就是拖最后一条往上拖等于原地不动）。处理函数不接受时不 `preventDefault`：
  指针不会显示成"可以放下"，事件继续交给外层。
- 拖**分组**时按**整块分组区域**的上下半区判定，不只按标题——标题只有四十来像素高，
  指针几乎总是落在条目区，只看标题会得到"没有落点"，看起来就是"拖不动"。
- 分组落点用**全量下标**计算（筛选时可见列表是子集，用可见下标会错位）。
- 排序是**任意位置**，不是相邻一格：宿主侧为此加了
  `POST /group/move-to`、`POST /item/move-to`（既有的 `/group/move`、`/item/move` 是 ±1，
  给 ⋯ 菜单的「上移/下移」用）。拖到自己身上是空操作。
- 代价说明：整行可拖意味着**按住行拖动不会再选中文本**——命令行要复制请用 ⋯ 菜单的「复制命令」。
  这也是文件列表/标签页那边的常规取舍。

### 面板会记住自己

选中哪条、哪些分组收起、筛选词、是否跟随底部都记在 localStorage + 模块级缓存里。
**切到别的面板再回来，右栏还停在原来那条日志上**，不用重新点。运行实例因为条目被删
而找不到时，会自动退到「最近一次失败的运行」。

### 给模型的工具

插件注册五个工具（需要组合里有 `tools` 服务）：前两个**只读**（看状态、读日志），后三个**接管运行实例**
（启动 / 停止 / 重启）—— 让模型自己就能「改完代码重启那个服务」，不必让用户回面板点按钮。

| 工具 | 作用 |
|---|---|
| `launcher_status` | 列出分组/启动项/运行实例的状态、退出码、pid、目录、命令、日志文件路径；**不含日志正文** |
| `launcher_log` | 读某个运行实例的输出：默认只回**关键行**（`Caused by` / `ERROR` / `Exception` / `BUILD FAILURE` / `ClassNotFound` …，上限 120 行）并附日志文件路径；`mode:"tail"` 取尾部、`mode:"full"` 才全量；`range:"12~45"` / `range:"signal"` / `range:"tail200"` 精确取段（面板里那个引用就是这么被解析的）；`grep` 过滤；按 `run` id 或 `item`/`group` 名字定位（不给就取最近一次失败的运行） |
| `launcher_run` | **启动**一个启动项（等价于点面板上的运行）：按 `item` 模糊匹配 + `group` 收窄；已在跑的不重复启动，而是提示改用 `launcher_restart` |
| `launcher_stop` | **停止**运行实例：按 `run` id 或 `item`/`group` 定位，默认 SIGINT + 宽限期，`force: true` 立刻终止；只停还活着的 |
| `launcher_restart` | **重启**：先停（可 `force`）、**等它真的落终态**（`stop` 只送 SIGINT，立刻重启会撞端口占用）、再用同一份清单定义起回来；进程赖着不退时如实报错 |

于是真实流程变成：你在启动器里看到服务炸了 → 回到对话说一句「启动器里那个 admin-service
为什么炸了」→ 模型自己去读日志（只读关键行，不吃 token）；改完代码也不用你点面板，
一句「重启一下那个服务」它就用 `launcher_restart` 停旧起新（会等旧进程真的退出，避免端口占用）。

### 一个真实事故：shell 的交互提问会顶住 PTY

`zsh -lic` 会加载用户的 `.zshrc`，而 oh-my-zsh 的自动更新检查会打印
`[oh-my-zsh] Would you like to update? [Y/n]` 并**等一次按键**。没人按键时命令根本不会执行 ——
面板上显示「运行中」，其实什么也没跑（踩过：某个启动项卡在这一行）。
所以子进程环境里固定加两个 oh-my-zsh 官方开关：`DISABLE_AUTO_UPDATE=true` 与
`DISABLE_UPDATE_PROMPT=true`（仍按用户 `.zshrc` 加载环境，只是不再停下来问）；启动项自己配了同名变量时以它为准。

## HTTP 面

同源，仅回环（非回环来源直接 403；`Host` 头也参与判定，IPC 桥接没有 socket 信息时放行）。
用户填错（空命令、超上限）回 400，宿主 bug 回 500 并记栈——两种不混成同一个状态码。

| 路由 | 说明 |
|---|---|
| `GET /api/dsh-launcher/state` | 清单 + 运行列表 + shell + 清单文件路径 |
| `GET /api/dsh-launcher/runs` | 运行列表（轮询用，不重读清单） |
| `GET /api/dsh-launcher/log?run=&from=` | 按绝对偏移取日志增量（读取非消费） |
| `POST /api/dsh-launcher/start` | `{ group, item }`：按清单定义启动 |
| `POST /api/dsh-launcher/stop` | `{ run, force? }`：先 SIGINT，宽限期后整棵树终止 |
| `POST /api/dsh-launcher/clear` | 丢弃已保留日志，保留总偏移 |
| `POST /api/dsh-launcher/remove` | 移除已结束的实例 |
| `POST /api/dsh-launcher/group/{create,update,remove,move}` | 分组的增改删移（`move` 是 ±1，给「上移/下移」） |
| `POST /api/dsh-launcher/group/move-to` | `{ id, before }`：把分组挪到 `before` 之前（拖拽排序；`before` 为 null = 末尾） |
| `POST /api/dsh-launcher/item/{create,update,remove,move}` | 条目的增改删移（含 `kind`） |
| `POST /api/dsh-launcher/item/move-to` | `{ group, item, toGroup, before }`：条目换位/换组（拖拽） |

写路由都返回写完之后的最新清单，客户端不用再多跑一趟。日志走**偏移增量轮询**（600ms）
而不是 SSE：在 Electron 的 IPC 桥接与普通 http 两种载体下行为一致；真机实测每 300ms
一行的心跳能准点到达。

## 已知边界

- **只 run，不 debug**：不接 DAP，不注入 `--inspect`，不解析依赖树。
- 右栏「运行日志」tab 是**会话级**的（插槽本身按 session 划分），但它看的运行实例是全局的，
  所以任何会话打开它都会看到同一批实例。
- 一条运行 = 一条命令行，**没有交互输入**（面板给的是实时日志，不是可输入的终端屏）。
  要交互时用内置终端；想对长驻服务收尾，用「停止」（SIGINT）或「强制结束」。
- 不模拟跨行光标寻址与整屏重绘，所以 `vim`/`htop` 这类全屏 TUI 在日志里不可读
  （行内的 `\r` 回车、`K` 擦除、SGR 颜色/256 色/真彩色、`\t` 制表位都按真终端语义还原）。
- 宿主半侧代码改动需要重启 DSH（见上）。
- 运行实例保留在进程内，DSH 退出即消失（不跨重启持久化）；清单跨重启保留。
